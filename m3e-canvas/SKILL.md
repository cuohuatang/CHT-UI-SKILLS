# 11 · m3e-canvas 可拖拽 UI 设计 — 实战分册

把用户的 UI 设计需求变成 **可拖拽的 M3E 画布设计**：AI 按协议生成设计 JSON → 压缩进分享链接 → 交付「侧边栏内嵌」与「卡片/链接」双模式 → 用户在画布拖改 → 导出 vibe-coding 提示词 → 按用户指令决定是否喂给 AI 代码生成。

> 上游：`oil-ui`（第 9 项）定设计方向后，可选择本分册出**可拖改原型**（替代 draw-ui 的静态稿）；也可独立触发。

## 触发

用户表达 UI 设计意图且需要**可拖改/可交互原型**时，例如：
- 「设计一个 XX 页面 / 界面 / UI」
- 「做一个 XX App 的界面」
- 「帮我画个 XX 的界面」
- 「设计 XX 的落地页 / 详情页 / 首页」
- 提到「可拖拽」「画布」「原型」「边看边改」「M3E」「Material 3」

## 工作流（六步）

### 第 1 步：需求收集（四象限法）

- **已知直接执行**：需求明确就直接生成设计，不问多余问题。
- **信息缺失最多问 3 个关键问题**（按重要性）：① 什么类型的页面/App？② 手机还是桌面？③ 主题色/风格偏好？
- **主动补充知识与指出前提错误**：例如用户要求的布局违反 M3 规范（如手机屏硬塞 6 列网格），主动指出并给替代方案。
- **共同未知**：转成可验证假设，用画布快速试。

默认值（用户未指定时）：手机（phone）/ Android / 紫色主题 / 3 屏 / 使用用户的对话语言。

### 第 2 步：生成设计 JSON

严格按 `references/agent-spec.md` 协议生成（协议全文见该文件，含全部字段与 38 种部件种类表）。要点：

- 顶层：`title`、`brief`、`frame:"phone"`、`platform`（android/web）、`paletteKey`（purple|blue|green|coral|amber|teal|mono）、`theme`（可选）、`frames`、`groups`。
- `frames`（屏幕）：手机 **412×892**，桌面 **1280×800**，并排放置、**间隔 80**。每屏有 `id`、`name`，可加 `note`、`swipe`。
- `groups`（部件组）：坐标为**画布坐标 = 屏幕 x/y + 部件偏移**；同族部件可连成 `axis:"x"`（按钮并排）或 `axis:"y"`（列表堆叠）；后面的组画在前面的组上面。
- 每屏一个 `topAppBar`，主屏一个 `bottomNav`（各屏 tabs 一致、`selected` 指向本屏），3–5 屏足够。
- 真实文案（用用户语言，不用 lorem ipsum）；导航闭环（列表行开详情、详情可返回 `"to":"back"`、FAB 开表单）。
- 每个部件必须含 `id`、`kind`、`label`（可空串）、`icon`（Material Symbols 名或 null）、`variant`。
- 简化优先：用默认 `"variant":"filled"` 和默认尺寸；`"icon": null` 留空；不加凑数部件；JSON 总长 < 100KB；图片用 `"src":"https://…"` 不嵌数据。

### 第 3 步：构造分享链接

1. 把 JSON 保存为文件（如 `design.json`）。**不要 inline 进 shell 命令**（引号会断）。
2. 运行脚本（当前分册目录下）：

   ```bash
   python scripts/make_link.py design.json
   ```

3. 得到 `https://lnkiai.github.io/m3e-canvas/#docz=…` 链接。
4. **不要自校验/自解码 JSON**——画布打开时会自动检查并提示错误。

### 第 4 步：交付双模式（用户自选，可自由切换）

两种模式**每次都同时提供**，由用户选择，且可随时切换：

- **模式 A · 侧边栏内嵌**：把分享链接贴到豆包右侧边栏打开 → 直接在侧边栏内拖改（已通过浏览器环境交互验证）。
- **模式 B · 卡片/链接**：把链接交付给用户，浏览器/客户端点开拖改。

若已本地部署 M3E Canvas（`git clone lnkiai/m3e-canvas` + `npm install` + `npm run dev` → `localhost:3000`），可把链接域名换成 `localhost:3000` 提供本机直连选项（仅同机可达；豆包侧边栏推荐用公网在线版）。

### 第 5 步：导出提示词

用户拖改完成后，在画布右上角 **「提示词」** 按钮导出 prompt（支持编辑后复制、或保存单屏 PNG）。

### 第 6 步：代码生成（听用户指令）

设计交付后，**先呈现 prompt，询问用户是否同意把提示词喂给 AI 代码生成**。未获用户指令前，不自动执行任何代码生成/部署动作。

## 注意事项

- 分享链接很长（几千字符）是**正常**的：整个设计都在链接里，无任何服务器存储。
- 生成设计后不要自己跑代码验证 JSON——画布打开时即校验。
- 多轮修改：用户说「改 XX」时，直接修改对应 JSON 字段、重新生成链接交付，保持同一设计延续。
